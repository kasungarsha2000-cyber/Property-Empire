# Property Empire on Android

The Android app is a [Capacitor 8](https://capacitorjs.com/) shell around the same Vite build that runs in
browsers. The rules engine, the 3D board (Three.js in the system WebView), saves and the LAN protocol are
shared with the web version; there is no second copy of the game logic.

| Item | Value |
|---|---|
| Project | `android/` (generated by `npx cap add android`, then customised) |
| App id | `com.propertyempire.game` (change in `capacitor.config.ts` and `android/app/build.gradle` before publishing) |
| SDK levels | minSdk 24, compileSdk 36, targetSdk 36 (`android/variables.gradle`) |
| WebView | Android System WebView 111 or newer; older devices see `webview-update.html` |
| Orientation | Portrait on phones; Android 16 lets large screens rotate, and the layout supports it |
| Permissions | `INTERNET` (LAN play). `VIBRATE` is added by the Haptics plugin. Nothing else. |
| Plugins | `@capacitor/app` (Back button, pause/resume), `@capacitor/haptics`, `@capacitor/share` |

## Requirements

- Node.js 22.12 or newer and `npm ci` in the project root.
- JDK 21 (Android Studio bundles one).
- Android SDK with platform 36 and build tools — install Android Studio, or the command-line tools, then set
  `ANDROID_HOME` (or create `android/local.properties` with `sdk.dir=/path/to/Android/sdk`).

## Build and run

```bash
npm ci
npm run android:sync     # npm run build + copy apps/web/dist into the Android project
npm run android:open     # open the project in Android Studio, then Run ▶ on a device or emulator
```

Command-line debug APK:

```bash
npm run android:build    # build, sync and ./gradlew assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk
```

Release builds: `node scripts/android-build.mjs release` produces an unsigned APK. Sign it with your own
keystore (Android Studio → Build → Generate Signed App Bundle / APK) before distributing.

## Install on a test device

1. On the phone enable **Developer options → USB debugging** (tap *Build number* seven times in *About phone*).
2. Connect it by USB and accept the prompt, then either press **Run** in Android Studio or run
   `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`.
3. Without USB, copy the APK to the phone and open it; allow *Install unknown apps* for the file manager.

## Playing on Android

- **Play solo**: computer opponents, optional extra people on the same phone (*Players on this device*). Works
  fully offline; saves are kept in the app's IndexedDB and written again when the app goes to the background.
- **Host LAN game / Join LAN game**: the game server is the existing Node host. Run `run.bat` (Windows) or
  `npm run start:lan` on a computer, note the printed Wi-Fi address (for example `192.168.1.5:3001`) and enter it
  in the app's *Host computer* field. One player creates the room (from a phone or a browser); others join with
  the six-character room code. The app remembers the last host address and offers **Rejoin LAN game** after
  interruptions. Browsers on the same network can join the same room.
- A phone cannot host a LAN game by itself: hosting needs the Node server. See *Known limits* below.

## How the Android shell is configured

- `server.androidScheme: 'http'` serves the app from `http://localhost`, so connecting to `ws://<lan-ip>:3001/ws`
  is not blocked as mixed content. `http://localhost` is still a secure context for storage and crypto APIs.
- `res/xml/network_security_config.xml` permits cleartext because LAN hosts use plain `ws://` on private
  addresses, which Android cannot whitelist by range. The app makes no other network requests.
- The LAN server accepts WebSocket connections from the app origins (`http://localhost`, `https://localhost`,
  `capacitor://localhost`) in addition to same-host browser pages. If you set `ALLOWED_ORIGINS`, include
  `http://localhost` to keep the app working.
- `SystemBars.insetsHandling: 'native'` with `viewport-fit=cover`: the WebView is padded on older WebViews and
  edge-to-edge on newer ones, where the UI uses `env(safe-area-inset-*)`.
- `apps/web/src/platform.ts` connects Android Back to the in-app layer stack (dialog → sheet → preview →
  card → decision panel → game menu; at the main menu the app is moved to the background), saves and stops the
  render loop on pause, resumes on return, and routes haptics through the Haptics plugin.
- The splash screen and launcher icons are original artwork rendered into `res/mipmap-*` and
  `res/drawable*/splash.png`; `android/store-icon-512.png` is the 512 px store icon.

## Known limits

- **Phone-only hosting** is not implemented. The host is the Node server (`apps/server`); running it on a phone
  would need an embedded WebSocket server in a native plugin. The room protocol is ready for it, but it was out
  of scope without devices to test on.
- The app does not read Android's system font scale; use **Settings → Text size**.
- Building and testing the APK requires the Android SDK, which this environment could not download.
